Regularized regression

Basic idea: fit a regression model and penaliza (or shrink) large coefficients.

Pros

  • Can help with the bias/variance tradeoff
  • Can help with model selection

Cons

  • May be computationally demanding on large data sets
  • (In general) Does not perform as well as random forests and boosting.

A motivating example

Assume the regression model

\[ Y = \beta_0 + \beta_1x_1 + \beta_2x_2 + \varepsilon \]

where \(x_1\) and \(x_2\) are nearly perfectly correlated (co-linear), Then, you can approximate this model by:

\[ Y = \beta_0 + \left(\beta_1 + \beta_2\right)x_1 + \varepsilon \]

The result is:

  • You will get a good estimate of \(Y\).
  • The estimate of \(Y\) will be biased.
  • We may reduce variance in the estimate.

set.seed(1, sample.kind = "Rounding")
## Warning in set.seed(1, sample.kind = "Rounding"): non-uniform 'Rounding'
## sampler used
# Define outcome "y" and predictors "x".
covnames <- names(prostate[-(9:10)])
y <- prostate$lpsa
x <- prostate[,covnames]
# Create test set predictors and outcomes.
train.ind <- sample(nrow(prostate), ceiling(nrow(prostate))/2)
y.test <- prostate$lpsa[-train.ind]
x.test <- x[-train.ind,]
# Create training set predictors and outcomes
y <- prostate$lpsa[train.ind]
x <- x[train.ind,]
# Define p, the number of predictors
p <- length(covnames)
# Initialize the list of residual sum squares
rss <- list()
# Loop through each combination of predictors and build models
for (i in 1:p) {
    # Compute matrix for p choose i predictors for i = 1...p (i \times p matrix)
    Index <- combn(p,i)
    # Calculate RSS of each combination of predictors.
    rss[[i]] <- apply(Index, 2, function(is) {
        # Take each combination (or column of Index matrix) and create formula for regression
        form <- as.formula(paste("y~", paste(covnames[is], collapse="+"), sep=""))
        # run LR with combination of predictors on training data
        isfit <- lm(form, data = x)
        # predict outcome for all training data points
        yhat <- predict(isfit)
        # Calculate RSS for predictions on Training data.
        train.rss <- sum((y-yhat)^2)
        # Predict outcome for all test data points
        yhat <- predict(isfit, newdata = x.test)
        # Calculate RSS for predictions on test data
        test.rss <- sum((y.test - yhat)^2)
        # Store each pair of training and test residual sum of squares as a list
        c(train.rss, test.rss)
    })
}

# Set up plot
plot(1:p, 1:p, type = "n", ylim = range(unlist(rss)), xlim = c(0,p), 
     xlab = "Number of predictors", ylab = "RSS", 
     main = "Prostate Cancer Data - Training vs Test RSS")
# Add data points for training and test RSS
for( i in 1:p) {
    # Plot training residual sum squares in blue
    points(rep(i, ncol(rss[[i]])), rss[[i]][1,], col = "blue", cex = 0.5)
    # Plot test residual sum squares in red
    points(rep(i, ncol(rss[[i]])), rss[[i]][2,], col = "red", cex = 0.5)
}
# Find the minimum training RSS for each combination of predictors
minrss <- sapply(rss, function(x) min(x[1,]))
#Plot line through the minimum training RSS data points in blue
lines((1:p), minrss, col = "blue", lwd = 1.7)
# Find the moinimum test RSS for each combination of predictors 
minrss <- sapply(rss, function(x) min(x[2,]))
#Plot line through the minimum test RSS data points in red
lines((1:p), minrss, col = "red", lwd = 1.7)
# Add legend
legend("topright", c("Train", "Test"), col = c("blue", "red"), pch = 1)

From here, we can see that the train set error always goes down, whereas the test set error exhibits a typical pattern: it goes down, hit a plateau and then goes back up again. This is because we are overfitting the data in the training set.

Model selection approach:

Split samples

No method better when data/computation time permits it. The approach is as follows:

  • Divide data into training/test/validation sets
  • Treat validation as test data, train all competing models on the trin data and pick the best one on validation
  • To appropriately assess performance on new data apply to test set
  • You may re-split and reperform steps 1-3

Two common problems

  • Limited data
  • Computational complexity

Decomposing expected prediction error

Assume \(Y_i = f\left(X_i\right) + \varepsilon_i\), then the expected prediction error is given by \(EPE\left(\lambda\right) = E\left[\left\{Y - \hat{f}_{\lambda}\left(X\right)\right\}^2\right]\).

Suppose that \(\hat{f}_{\lambda}\) is the estimate from teh training data and look at a new data point \(X = x^*\). Then

\[ E\left[\left\{Y - \hat{f}_{\lambda}\left(x^+\right)\right\}^2\right] = \underbrace{\sigma^2}_{\text{Irreducible}} + \underbrace{\left\{E\left[\hat{f}_{\lambda}\left(x^+\right)\right] - f\left(x^+\right)\right\}^2}_{\text{Bias}^2} + \underbrace{var\left[\hat{f}_{\lambda}\left(x_0\right)\right]}_{\text{Variance}} \]

Hard thresholding

When having less observations (samples) than covariates, the design matrix will be singular. Therefore, as a solution to this, for the model \(Y = f\left(X\right) + \varepsilon\) set \(\hat{f}_{\lambda}\left(x\right) = x'\beta\) and constrain only \(\lambda\) of the coefficients to be nonzero.

Selection problem is after choosing \(\lambda\) figure out which \(p-\lambda\) coefficients to make nonzero.

Regularization for regression

If the \(\beta_j\)’s are unconstrained:

  • They can explode
  • And hence are susceptible to very high variance

To control variance, we might regularize/shrink the coefficients

\[ PRSS\left(\beta\right) = \sum_{j=1}^{n}{\left(Y - \sum_{i=1}^{m}{\beta_{1i}X_{ij}}\right)^2} + P\left(\lambda;\beta\right) \] where \(PRSS\) is a penalized form of the sum of squares. Things that are commonly looked for:

  • Penalty reduces complexity and variance
  • Penalty respects structure of the problem

Ridge regression

The problem is stated as solving

\[ \sum_{i=1}^{N}{\left(y_i - \beta_0 - \sum_{j=1}^{p}{x_{ij}\beta_j}\right)}^2 + \lambda\sum_{j=1}^{p}\beta_j^2 \] which is equivalent to solving

\[ \sum_{i=1}^{N}{\left(y_i - \beta_0 - \sum_{j=1}^{p}{x_{ij}\beta_j}\right)}^2 \]

subject to \(\sum_{j=1}^{p}{\beta_j^2} \leq s\) where \(s\) is inversely proportional to \(\lambda\). Inclusion of \(\lambda\) makes the problem non-singular even if \(X'X\) is not invertible.

Tuning parameter \(\lambda\)

We can see that \(\lambda\) controls the size of the coefficients and the amount of regularization. Moreover, as \(\lambda\rightarrow 0\), we obtain the LS solution, whereas as \(\lambda\rightarrow \infty\) we have \(\hat\beta = 0\).

So, taking the parameter can be done with cross-validation or techniques that help to find the optimal tradeoff of bias for variance.

Regularized Regression - LASSO (Least Absolute Shrinkage and Selection Operator) regression

It is similar to ridge regression, with slightly different penalty term:

\[ \sum_{i=1}^{N}{\left(y_i - \beta_0 - \sum_{j=1}^{p}{x_{ij}\beta_j}\right)}^2 + \lambda\sum_{j=1}^{p}\left|\beta_j\right| \] which is equivalent to solving

\[ \sum_{i=1}^{N}{\left(y_i - \beta_0 - \sum_{j=1}^{p}{x_{ij}\beta_j}\right)}^2 \]

subject to constraint \(\sum_{j=1}^{p}{\left|\beta_j\right|} \leq s\) where \(s\) is inversely proportional to \(\lambda\). NOTE: LASSO effectively performs model selection (choose subset of predictors) while shrinking other coefficients, whereas ridge regression only shrinks the coefficients.

  • Combining classifiers improves accuracy
  • Combining classifiers reduces interpretability
  • Boosting, bagging, and random forests are variants on this theme

The basic intuition behind majority vote

Suppose we have 5 completely independent classifiers. If accuracy of each is \(70\%\), then, the majority vote accuracy (the probability of the majority of the models achieving \(70\%\) at the same time) is:

\[ \text{Majority vote accuracy, MVA} = \mathbb{P}\left(\text{3 correct, 2 wrong}\right) + \mathbb{P}\left(\text{4 correct, 1 wrong}\right) + \mathbb{P}\left(\text{5 correct}\right) \]

therefore, under the independent assumption, this might be calculated using the binomial distribution. So

\[ \text{MVA} = 10\left(0.7\right)^3\left(0.3\right)^2 + 5\left(0.7\right)^4\left(0.2\right) + \left(0.7\right)^5 \approx 83.7 \]

Note: using 101 classifiers, this quantity becomes \(99.9\%\).

The approaches for combining classifiers includes:

  • For similar classifiers: bagging, boosting and random forests
  • For different classifiers: model stacking and model ensembling

Forecasting

Let’s talk about forecasting, which is the name used for predictions in time series data. Financial data is a kind of time series data, as we can see in the following link: Google Finance

The main difference is that data is time-dependent. Here, we are going to look for some components:

  • Trends - long term increase or decrease.
  • Seasonal patterns - patterns related to time (week, month, year, etc.)
  • Cycles - patterns that rise and fall periodically

Therefore, the approach of subsampling into train/test data sets is more complicated. Note: a similar problem arises when dealing with spatial data for the same reasons: dependency between nearby observations and location specific effects.

Typically, the goal is to predict one or more observations into the future (which in regression would be extrapolation). All standard predictions can be used (with caution/sense!).

Be careful with spurious correlation, as this kxcd joke shows with geographical maps: http://xkcd.com/1138/ (red areas are the high density in population places).

Unsupervised prediction

Supervised prediction is regarded as prediction where you know what the labels are. Unsupervised prediction is when you do not know the labels for prediction. In those cases, to build a predictor you

  • Create clusters
  • Name clusters
  • Build predictor for clusters

so that, in a new data set, you predict clusters
